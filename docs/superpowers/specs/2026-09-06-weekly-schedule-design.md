# 每周课程表设计文档

> 状态：已确认
> 日期：2026-09-06
> 参考样式：用户提供的 12 节课程表截图
> 首页方案：B「紧凑周摘要」
> 编辑方案：B「课程列表 + 编辑面板」

## 1. 目标

在个人网站中加入一套服务器保存的每周课程表：访客可以在首页和完整课表页查看当前周课程，站主通过现有管理员登录进入管理页，新增、修改和删除课程。课程按学期周次自动筛选，进入新的一周后自动显示新周内容。

## 2. 已确认的产品决策

- 课表数据保存到服务器，不使用浏览器本地存储。
- 使用现有 `/admin/login` 的 Session、CSRF 和管理员权限。
- 周次采用“学期开始日期 + 总周数”计算方式。
- 学期开始日期代表第 1 周的周一。
- 首页使用紧凑周摘要，不在首屏放完整 7 天 × 12 节矩阵。
- 完整课表页显示完整周视图。
- 管理页采用课程列表加编辑面板，而不是直接在表格中拖拽编辑。
- 时间轴按照截图固定为 12 节；课程可以跨连续节次，但本期不开放修改节次时间模板。

## 3. 页面结构

### 3.1 首页

首屏右侧的 Wanderer 卡片上移，卡片下方放置“本周课表”紧凑摘要。摘要包含当前周次、日期范围和本周课程列表，优先展示当天课程，再展示本周后续课程。

课表卡片是只读入口，点击后跳转到 `schedule.html`。没有课程时显示“本周暂无课程”，读取失败时显示可理解的错误状态，不遮挡主页其他内容。

### 3.2 完整课表页

`schedule.html` 使用截图中的结构：

- 顶部显示学期周次和当前日期范围；
- 日期栏显示周一至周日；
- 左侧显示 1–12 节及对应时间；
- 课程以半透明彩色块呈现，显示课程名、老师和地点；
- 提供上一周、本周、下一周操作；
- 当前日期使用高亮边框；
- 学期开始前显示“未开学”，学期结束后显示“课程已结束”；
- 移动端允许横向查看完整周表，并保持左侧节次可辨识。

页面提供“进入管理”入口；未登录访问时由服务器跳转到 `/admin/login`，登录后才可进入管理页。

### 3.3 管理页

新增受保护的 `/admin/schedule` 页面，沿用现有后台的视觉和权限体系。

- 顶部显示当前学期、当前周次和保存状态；
- 中间显示课程记录列表；
- 每条记录显示课程名、星期、节次、地点和周次；
- “新增课程”打开空白编辑面板；
- “编辑”打开已有课程面板；
- “删除”需要二次确认；
- 保存成功后停留在管理页并刷新列表；
- 未登录访问重定向到 `/admin/login`。

编辑面板字段：

- 课程名称；
- 授课老师；
- 上课地点；
- 星期；
- 起始节次；
- 结束节次；
- 上课周次；
- 课程颜色。

周次选择支持全选、清空、单双周和自定义周次。一个课程记录对应一个星期和一段连续节次；同一课程若有多个星期或不连续时段，可建立多条记录，保持数据模型简单且易于检查冲突。

## 4. 时间轴

课程表固定使用以下 12 节：

| 节次 | 时间 |
| --- | --- |
| 1 | 08:00–08:45 |
| 2 | 08:55–09:40 |
| 3 | 10:00–10:45 |
| 4 | 10:55–11:40 |
| 5 | 13:30–14:15 |
| 6 | 14:25–15:10 |
| 7 | 15:30–16:15 |
| 8 | 16:35–17:20 |
| 9 | 18:00–18:45 |
| 10 | 18:55–19:40 |
| 11 | 20:00–20:45 |
| 12 | 20:55–21:40 |

## 5. 数据模型

服务器数据目录中的 `schedule.json` 保存完整课表，数据目录继续与公开仓库隔离：

```json
{
  "version": 1,
  "termStart": "2026-09-07",
  "totalWeeks": 20,
  "courses": [
    {
      "id": "course-1",
      "name": "计算物理基础",
      "teacher": "赵虎",
      "room": "九 202",
      "weekday": 3,
      "startPeriod": 1,
      "endPeriod": 2,
      "weeks": [1, 2, 3, 4, 5],
      "color": "mint"
    }
  ]
}
```

字段约束：

- `termStart` 为合法日期且必须是周一；
- `totalWeeks` 为 1–60 的整数；
- `weekday` 为 1–7，分别代表周一至周日；
- `startPeriod` 和 `endPeriod` 为 1–12 的整数，且起始节次不晚于结束节次；
- `weeks` 为去重、升序的周次数组，所有值位于 1–`totalWeeks`；
- `color` 只能使用预设色板，例如 `mint`、`pink`、`blue`、`orange`；
- 用户输入全部通过 DOM `textContent` 或安全属性写入，避免把课程内容当作 HTML 执行。

## 6. 周次计算与自动更新

前端和服务端共用相同的日期规则：以北京时间 `Asia/Shanghai` 的日期为准，以 `termStart` 为第 1 周周一，每 7 个自然日递增一周。

- 当前日期早于 `termStart`：显示第 1 周并附加“未开学”；
- 当前日期位于学期内：显示对应周次；
- 当前日期晚于学期末：显示“课程已结束”，默认不再显示课程；
- 查看历史或未来周时，手动切换不受当前周限制；
- 页面打开、回到前台和北京时间跨周边界时重新计算；
- 首页摘要、完整课表和管理页使用同一个纯函数，避免三个页面出现不同周次。

## 7. API 与权限

- `GET /api/schedule`：公开返回经过校验的课表数据；
- `GET /api/admin/schedule`：登录后返回管理用课表数据；
- `PUT /api/admin/schedule`：登录并通过 CSRF 校验后保存完整课表；
- 管理 API 使用现有 `requireAuth`、`requireCsrf` 和统一错误响应；
- 公开静态文件白名单不开放服务器数据目录；
- 服务器写入使用临时文件加原子替换，避免进程中断留下半份 JSON；
- 保存失败时保留内存中的编辑内容并提示用户重试，不显示成功状态。

## 8. 校验与错误处理

- 必填字段为空或只有空格时返回字段级错误；
- 非法日期、星期、节次、周次或颜色返回 400；
- 同一星期、同一周次且节次重叠的课程返回冲突错误并阻止保存；
- 课表文件不存在时返回默认空课表和 12 节时间轴；
- 课表文件损坏时记录服务端错误，公开页显示“课表暂时无法加载”，不影响其他页面；
- 未登录管理请求返回 401 或跳转登录页；
- CSRF 失败返回 403；
- 移动端加载或网络失败时保留可重试的错误状态。

## 9. 实现边界

本期包含：服务器保存、公开读取、管理员增删改、周次计算、冲突校验、首页摘要、完整课表页、响应式和可访问性支持。

本期不包含：多人账号、课程共享权限、拖拽排课、导入教务系统、ICS 导出、通知提醒、自动识别图片课表、修改 12 节时间模板。

## 10. 测试与验收

自动测试覆盖：

- 12 节时间与截图一致；
- 学期前、学期中、学期末周次计算正确；
- 课程按星期、周次和节次筛选正确；
- 课程新增、修改、删除和 JSON 持久化正确；
- 非法字段、空字段和节次冲突被拒绝；
- 未登录用户不能读取管理接口或保存课表；
- 公开 API 不泄露服务器数据目录路径；
- 首页、完整课表页和后台页面包含正确入口与脚本钩子；
- 空课表、读取失败和保存失败都有稳定界面状态。

浏览器验收覆盖桌面端和移动端：确认首页右侧卡片上移、紧凑课表位于右下方、点击可进入完整课表、周次切换正确、后台登录后可新增和编辑课程，以及无控制台错误。
