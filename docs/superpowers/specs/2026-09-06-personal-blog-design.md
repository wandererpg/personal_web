# 个人博客 MVP 设计文档

> 状态：已确认，待实现
> 日期：2026-09-06
> 视觉方案：A「星际档案库」

## 1. 目标

将首页“值得留下的想法”板块改造成“我的博客”，用于发布项目记录、学习总结、知识分享和图文内容。博客内容保存在仓库中，提交并上传后对所有访客可见，并保留 Git 版本记录。

参考 [DrTonks/tonks-home](https://github.com/DrTonks/tonks-home) 的数据驱动组织方式，文章列表由统一内容索引生成，不直接把文章内容硬编码在页面结构中。

## 2. MVP 范围

- 首页显示 3 篇最新博客文章。
- 博客列表页显示全部文章。
- 独立文章页显示标题、封面、元信息、正文和正文图片。
- 支持文章摘要、分类、标签、发布日期和预计阅读时间。
- 支持 Markdown 文章和 JPG、PNG、WEBP 等常见图片。
- 文章和图片通过仓库文件发布，不包含在线后台、账号、数据库或访客评论。

## 3. 页面结构

### 3.1 首页博客区

- 保留当前星空背景、液态玻璃卡片和动态氛围。
- 区块标签改为 `02 / Blog archive`。
- 标题改为“我的博客。”。
- 引导文案改为“记录正在学习、制作和重新理解的东西。”。
- 第一篇最新文章使用大尺寸主卡片，显示封面、标题、摘要和标签。
- 另外两篇使用紧凑卡片，显示日期、分类、标题、摘要和跳转箭头。
- “查看全部博客”跳转到博客列表页。

### 3.2 博客列表页

当前 `notes.html` 保留为列表页入口，以避免已有链接失效；页面可见标题和导航统一改为 Blog / 我的博客。

- 顶部显示“我的博客。”和简短介绍。
- 文章按发布日期倒序排列。
- 每条文章包含封面缩略图、日期、分类、标题、摘要、标签和阅读时间。
- 首篇文章可使用更大的档案卡片，其余文章使用统一列表卡片。
- 点击卡片进入 `post.html?slug=<slug>`。

### 3.3 文章详情页

- 顶部显示返回博客、分类、发布日期和阅读时间。
- 主标题和摘要置于封面图前方或下方的玻璃内容层。
- 正文使用清晰的阅读列宽，支持二级标题、段落、列表、代码块、链接和图片。
- 图片支持说明文字，单图居中展示，多图可组成连续图组。
- 页面底部提供上一篇、下一篇和返回博客入口。

## 4. 视觉与动效

整体延续当前 C2 深空界面：深蓝黑底色、星云渐变、电光青强调色、细线框和半透明玻璃层。

- 文章封面使用低饱和度渐变遮罩，保证标题对比度。
- 玻璃卡片增加轻微的背景透出和边框折射，不使用鼠标跟随光晕。
- 卡片悬停仅使用轻微上浮、边框高亮、封面慢速放大和箭头旋转。
- 按下卡片时不改变布局位置，不产生下沉偏移。
- 列表进入时使用短距离淡入和错峰出现；文章阅读页只保留必要过渡。
- 星空动态保持低频、低对比度，不能干扰正文阅读。
- 遵循 `prefers-reduced-motion`，减少或关闭非必要动画。

## 5. 内容目录与数据结构

建议目录：

```text
posts/
  index.json
  first-project.md
  learn-css.md

assets/
  blog/
    first-project/
      cover.jpg
      image-01.jpg
    learn-css/
      cover.png
```

`posts/index.json` 作为文章索引，单条记录包含：

```json
{
  "slug": "first-project",
  "title": "把一个想法做成可运行的东西",
  "date": "2026-09-06",
  "category": "MAKING",
  "excerpt": "记录一次从想法到可使用结果的过程。",
  "cover": "assets/blog/first-project/cover.jpg",
  "tags": ["Project", "Process"],
  "readingTime": "6 min",
  "content": "posts/first-project.md"
}
```

页面加载索引后按 `date` 倒序排列：首页取前三条，列表页取全部，详情页依据 URL 中的 `slug` 加载对应 Markdown。

## 6. 发布流程

1. 在 `posts/` 新建 Markdown 文章。
2. 在 `assets/blog/<slug>/` 放入封面和正文图片。
3. 在 `posts/index.json` 增加文章元数据。
4. 本地预览并检查图片路径、文章链接和移动端布局。
5. 创建 Git Commit 并推送到 GitHub，服务器部署后即可对外发布。

网页内直接上传并自动发布不属于本次 MVP；该能力需要后端接口、文件存储和权限控制，后续可以在当前内容结构上扩展。

## 7. 错误处理与安全

- 索引文件不存在或 JSON 损坏时，页面显示空状态，不阻塞导航和音乐播放器。
- 文章文件不存在时显示“文章暂时无法读取”，并提供返回博客入口。
- 封面或正文图片加载失败时显示统一的占位背景，不出现破碎图片图标。
- 标题、摘要、标签等内容使用安全文本渲染；文章链接限制为安全协议。
- `slug` 只允许匹配索引中的文章，不能直接读取任意路径。

## 8. 响应式与可访问性

- 桌面端采用“主卡片 + 两张辅助卡片”的布局，文章详情页正文保持舒适阅读宽度。
- 移动端所有卡片改为单列，封面比例固定，避免文章标题被图片遮挡。
- 卡片使用语义化链接，整张卡片可点击，箭头作为装饰或辅助提示。
- 图片提供替代文本，代码块和链接保持键盘可访问。
- 焦点状态使用清晰描边，不能只依赖颜色或悬停效果表达状态。

## 9. 测试与验收

自动测试覆盖：

- 首页显示“我的博客”，旧的“值得留下的想法”标题不再出现。
- 文章索引可以解析，并按日期正确排序。
- 首页只显示最新三篇，列表页显示全部文章。
- 文章详情页能够依据合法 `slug` 加载正文和图片。
- 缺失索引、损坏索引、缺失文章和图片失败均有可读的降级状态。
- 所有文章卡片链接、图片路径和关键无障碍属性存在。

浏览器验证覆盖桌面端和移动端：首页主卡片、博客列表、文章详情、图片加载、返回导航、卡片悬停/按下反馈、键盘焦点和控制台错误。

## 10. MVP 边界

暂不包含：在线编辑器、网页上传后台、账号权限、数据库、评论、全文搜索、RSS、点赞、草稿箱、自动图片压缩和云端同步。
