# 博客三模块与在线发布后台设计

> 状态：已确认，待实施  
> 日期：2026-09-06  
> 适用项目：Wanderer.OS 个人网站

## 1. 目标

在现有仓库驱动博客的基础上，增加三个固定内容模块和一个仅站长可用的在线管理后台。站长可以登录后创建、编辑、预览和发布 Markdown 文章，上传封面与正文图片；访客只能浏览已发布文章，不能查看草稿或调用修改接口。

三个固定模块为：

- 我的项目：项目过程、阶段成果与复盘。
- 心得分享：实践经验、方法和个人判断。
- 日常学习：近期学习内容与知识整理。

## 2. 设计依据

编辑体验借鉴成熟内容系统的共同模式：

- Ghost 的专注写作画布和就地媒体插入。
- WordPress 的内容画布、文章设置栏和媒体上传反馈。
- Decap CMS 的仓库内容管理与 Git 发布工作流。

本项目不直接引入完整 CMS，而是采用自定义 Node.js 后台，以延续现有静态页面、Markdown 文件、Git 历史和 Wanderer.OS 视觉语言。

## 3. 访问面与权限边界

系统分为公开访问面和管理访问面。

### 3.1 公开访问面

- 首页继续展示最新三篇已发布文章，并显示所属模块。
- `notes.html` 展示“我的项目”“心得分享”“日常学习”三个模块。
- 点击模块进入该模块的已发布文章列表。
- 文章条目包含标题、创作时间、预计阅读时间、摘要、标签和可选封面。
- 点击文章进入 `post.html?slug=<slug>` 查看正文详情。
- 公开页面只读取发布索引，不能通过修改 URL 获取草稿。

### 3.2 管理访问面

- `/admin/login`：单管理员账号与密码登录。
- `/admin`：文章列表、模块筛选、状态筛选、搜索和新建文章入口。
- `/admin/editor`：Markdown 编辑、实时预览、文章设置、图片上传、保存草稿和发布。
- 草稿、私有预览、上传和发布接口均要求有效的服务端 Session。
- 公开页面不展示管理入口；安全性不依赖入口隐藏，所有管理 API 都执行服务端鉴权。

## 4. 管理后台界面

### 4.1 内容管理页

左侧显示三个模块以及草稿、已发布、媒体文件入口；主区域使用文章列表布局。每条记录显示：

- 标题与摘要。
- 所属模块。
- 草稿、已发布或待同步状态。
- 创作时间与最近更新时间。
- 编辑入口。

顶部提供搜索、模块筛选、状态筛选、排序和“新建文章”按钮。

### 4.2 Markdown 编辑器

编辑器采用“内容画布 + 设置栏”：

- 顶部操作区：返回列表、当前状态、保存草稿、私有预览、发布并同步。
- 主画布：标题输入、Markdown 编辑区和实时预览；桌面端可并排显示，移动端使用标签切换。
- 设置栏：模块、摘要、标签、Slug、封面和图片上传。
- 自动保存明确显示“保存中”“已保存”“保存失败”，同时保留手动保存按钮。
- 存在未保存修改时，离开页面前提示用户。

图片支持拖拽、粘贴和文件选择。上传完成后生成安全文件名，要求填写替代文字，并将对应 Markdown 图片语法插入光标位置。

## 5. 内容模型

公开索引继续使用 `posts/index.json`。发布记录统一包含：

```json
{
  "slug": "site-rebuild-log",
  "title": "个人网站重构日志",
  "module": "projects",
  "createdAt": "2026-09-06T14:32:08+08:00",
  "updatedAt": "2026-09-06T15:10:20+08:00",
  "publishedAt": "2026-09-06T15:12:00+08:00",
  "excerpt": "记录星际档案库的结构调整与取舍。",
  "cover": "assets/blog/site-rebuild-log/cover.webp",
  "tags": ["Website", "Design"],
  "readingTime": "6 min",
  "content": "posts/site-rebuild-log.md"
}
```

模块值固定为：

| 值 | 页面名称 |
| --- | --- |
| `projects` | 我的项目 |
| `insights` | 心得分享 |
| `learning` | 日常学习 |

现有文章的 `category` 和 `date` 在迁移时映射为 `module` 与 `createdAt`。公开索引只包含已发布记录，不保存草稿状态或私有文件路径。

## 6. 文件与私有数据

已发布内容沿用现有目录：

```text
posts/<slug>.md
assets/blog/<slug>/cover.webp
assets/blog/<slug>/<image-name>.webp
posts/index.json
```

草稿和暂存图片保存在 `BLOG_DATA_DIR` 指向的服务器私有目录中。该目录位于公开站点目录和 Git 仓库之外，并由服务器单独备份。编辑已发布文章时，后台先创建私有修订草稿；访客继续看到旧版本，直到站长重新发布。

## 7. 服务端架构

Node.js 服务负责：

- 提供现有公开静态资源。
- 管理登录 Session 与 CSRF 校验。
- 提供受保护的文章、草稿、上传、预览、发布和同步 API。
- 将发布内容写入 Markdown、图片目录和公开索引。
- 串行执行 Git 检查、Commit 与 Push。

Git 命令通过参数数组执行，不启用 Shell，也不拼接用户输入。发布前检查远程状态；如果远程分支无法快进同步，则停止发布并要求人工处理，不自动覆盖远程历史。

## 8. 保存与发布流程

### 8.1 保存草稿

1. 校验管理员 Session 和 CSRF Token。
2. 校验标题、模块、Slug、摘要、Markdown 正文和图片引用。
3. 原子写入私有草稿及元数据。
4. 返回保存时间和草稿版本号。

草稿不会写入 `posts/index.json`，不会进入 Git，也不会被公开静态服务器提供。

### 8.2 发布并同步

1. 获取发布锁，防止并发修改索引。
2. 检查远程分支是否可以安全快进。
3. 校验正文和媒体资源。
4. 将文章写入 `posts/<slug>.md`，将图片复制到 `assets/blog/<slug>/`。
5. 原子更新 `posts/index.json`。
6. 仅暂存本篇文章、对应图片和索引。
7. 创建包含文章标题的 Git Commit。
8. Push 到 GitHub，并返回 Commit ID。

如果 Push 失败，本地 Commit 保留，后台显示“待同步”并提供重试；草稿和正文不会丢失。Git 冲突不会自动合并或强制推送。

## 9. 安全要求

- 管理员用户名、密码哈希和 Session Secret 只通过环境变量提供。
- 密码不以明文写入代码、配置文件或 Git 历史。
- Session Cookie 使用 `HttpOnly`、`SameSite=Strict`；生产环境仅通过 HTTPS 发送。
- 所有修改接口必须校验 CSRF Token。
- 登录接口限速，连续失败后暂时锁定来源。
- 图片仅允许 JPEG、PNG 和 WebP，同时校验扩展名、MIME 与文件特征。
- 限制单张图片大小、单篇文章图片总量和请求体大小。
- MVP 禁止上传 SVG、HTML、脚本和可执行文件。
- Slug、文件路径和文件名由服务端校验或生成，阻止路径穿越。
- 私有数据目录绝不挂载为静态目录。

## 10. 错误与恢复

- 表单校验错误显示在对应字段旁，不清空已经输入的正文。
- 自动保存和图片上传失败时保留本地编辑状态并提供重试。
- 上传进度按文件显示，失败文件不影响已成功文件。
- 发布失败时明确区分内容校验、文件写入、Git 冲突、Commit 和 Push 错误。
- 索引采用临时文件加原子替换，避免中断产生半写入 JSON。
- 服务端日志记录操作类型、时间和结果，但不记录密码、Session、正文或敏感环境变量。

## 11. 测试与验收

自动测试覆盖：

- 未登录用户无法读取草稿或调用任何管理写入接口。
- CSRF 缺失或无效时拒绝修改。
- 公开索引和三个模块页面只包含已发布文章。
- Markdown 草稿创建、编辑、自动保存和重新发布。
- 图片类型、大小、文件特征、文件名和路径安全校验。
- 发布正确写入 Markdown、图片与索引，并创建范围正确的 Git Commit。
- Push 失败、远程分支冲突、上传中断和索引写入失败的恢复行为。
- 三模块导航、文章列表、详情、私有预览和编辑器关键交互。
- 桌面端、移动端、键盘操作与减少动态效果模式。
- 现有前台测试全部保持通过。

交付前运行完整测试、JavaScript 语法检查、Git 差异检查和本地 HTTP 冒烟验证。

## 12. MVP 非目标

本阶段不包含多作者权限、评论、定时发布、在线协作、富文本块编辑器、跨文章媒体库复用、文章删除、云对象存储、图片裁剪器和 Git 历史回滚界面。文章历史仍可通过 Git 追踪和回滚。

## 13. 部署要求

- 服务器能够长期运行 Node.js 服务。
- Nginx 或等效代理提供 HTTPS，并将站点流量转发至 Node.js。
- 服务器仓库使用已授权的 SSH Key Push 到 GitHub。
- 环境变量至少包含管理员用户名、密码哈希、Session Secret、私有数据目录、仓库目录和目标分支。
- 私有草稿目录纳入服务器备份，但不进入公开仓库。
